0. KISA CEVAP: MMKV DAHA PERFORMANSLI MI?  → EVET, belirgin şekilde.
--------------------------------------------------------------------------------

  AsyncStorage:
    - ASENKRON (her çağrı Promise). Eski mimaride köprü (bridge) üzerinden;
      Android'de SQLite/dosya tabanlı. Çok sayıda küçük okumada yavaş.
    - Açılışta veriyi `await` ile okumak zorundasın → "hidrasyon yarışı" ve
      kısa süreli boş/flicker durumları (örn. tema/dil ilk karede yanlış).

  MMKV (react-native-mmkv):
    - SENKRON, native C++ (mmap + protobuf), JSI tabanlı → köprü yok.
    - Pratikte ~10-30x daha hızlı; küçük KV okumaları neredeyse anlık.
    - SENKRON olduğu için modül yüklenirken `await` OLMADAN okunur →
      AppSettings/tema/dil/oturum cache'i ilk render'dan ÖNCE hazır olur,
      hidrasyon yarışı ve flicker BİTER. Bu, bu uygulamadaki asıl kazanç.
    - Bonus: dahili ŞİFRELEME desteği (encryption key) — aşağıdaki düz-metin
      parola sorununu (LoginScreen) çözmek için fırsat.

  GERÇEK KAZANÇ (bu projede):
    En büyük fayda ham hız değil, AppSettingsContext'teki tek büyük `multiGet`
    round-trip'ini ve onu bekleyen async hidrasyonu ortadan kaldırmaktır.
    Senkron okuma = ayarlar/tema/dil/oturum daha açılışta yerinde.

  ÖN KOŞULLAR (zaten sağlanıyor):
    - Native build gerekir (Expo Go değil). Proje zaten dev-client/EAS build
      (skia, reanimated, google-signin var) → sorun yok.
    - react-native-mmkv v3 New Architecture ister; app.json'da
      newArchEnabled:true → uyumlu.

3. GEÇİŞTE DİKKAT EDİLMESİ GEREKEN ÖZEL DURUMLAR (RİSKLER)
--------------------------------------------------------------------------------

3.1  FIREBASE AUTH PERSISTENCE  (en kritik)
  firebase.js: getReactNativePersistence(AsyncStorage) bir ASENKRON Storage
  arayüzü (getItem/setItem/removeItem → Promise) bekler. MMKV SENKRONDUR ve
  doğrudan verilemez. İki seçenek:
    (A) MMKV'yi async arayüze saran ince bir adaptör yaz:
          { getItem: k => Promise.resolve(storage.getString(k) ?? null),
            setItem: (k,v) => { storage.set(k,v); return Promise.resolve(); },
            removeItem: k => { storage.delete(k); return Promise.resolve(); } }
        ve getReactNativePersistence(adapter) ile ver.
    (B) Daha güvenli/az riskli: Firebase Auth için AsyncStorage'ı OLDUĞU GİBİ
        BIRAK, geri kalan her şeyi MMKV'ye taşı. (Tek paket bağımlılığı kalır
        ama auth oturumu riske girmez.)
  ÖNERİ: İlk fazda (B), test edildikten sonra istenirse (A).

3.2  MEVCUT VERİNİN GÖÇÜ (one-time migration)
  Kullanıcılarda zaten AsyncStorage'da kayıtlı ayar/oturum/cache var. MMKV'ye
  geçince bunlar OTOMATİK gelmez → ayarlar sıfırlanır, "son giriş" kaybolur.
  ÇÖZÜM: İlk açılışta tek seferlik göç:
    - AsyncStorage.getAllKeys() → ilgili key'leri oku → MMKV'ye yaz →
      bir "mmkv_migrated_v1" bayrağı set et → sonraki açılışlarda atla.
  KRİTİK key'ler: tüm AppSettings key'leri, cachedUserId, recentUsers,
  avatar_*, listGridStyle, allCornersRounded, pet_*, *_drafts, ai_* .
  (apicache_* / *_cache gibi büyük cache'ler göç ETMEYEBİLİR — yeniden dolar.)

3.3  DÜZ METİN PAROLA  (güvenlik fırsatı)
  LoginScreen `password_${email}` parolayı düz metin saklıyor. Geçiş anında:
    - MMKV'yi encryption key ile başlat (new MMKV({ id, encryptionKey })), VEYA
    - Parolayı tamamen expo-secure-store'a taşı (Keychain/Keystore).
  Migrasyon sırasında eski düz-metin key silinmeli.

3.4  BÜYÜK JSON BLOB'LAR
  feed_cache_v1, list_status_cache_*, cache_watchedTvShows, apicache_* büyük
  olabilir. MMKV bunları da hızlı tutar; yine de çok büyürse ileride bunları
  bir dosya/DB'ye almak düşünülebilir (şimdilik MMKV yeterli).

3.5  clear() DAVRANIŞI
  SettingsScreen.clear() → MMKV'de storage.clearAll(). Birden fazla MMKV
  instance (örn. şifreli auth ayrı, genel ayrı) varsa HEPSİ temizlenmeli.

4.1  TEK SARMALAYICI MODÜL (storage soyutlaması)
  Tüm dosyalar AsyncStorage'ı doğrudan import etmek yerine TEK bir modülden
  okusun → gelecekte tekrar değişim (veya hibrit) sınırlı kalır:

    // utils/storage.js
    import { MMKV } from "react-native-mmkv";
    const mmkv = new MMKV();
    export const storage = {
      getString: (k) => mmkv.getString(k) ?? null,
      set:       (k, v) => mmkv.set(k, v),
      delete:    (k) => mmkv.delete(k),
      getJSON:   (k) => { const s = mmkv.getString(k); return s ? JSON.parse(s) : null; },
      setJSON:   (k, v) => mmkv.set(k, JSON.stringify(v)),
      clearAll:  () => mmkv.clearAll(),
    };

  Avantaj: senkron API → çağıran yerlerde `await` ve loading state'leri kalkar
  (özellikle AppSettings, ProfileUi, translations, PetContext açılış okumaları).

4.2  GEÇİŞ SIRASI (düşük riskten yükseğe)
  1) utils/storage.js + react-native-mmkv kur, dev-client/EAS build al.
  2) Tek seferlik göç fonksiyonu (Bölüm 3.2) — App açılışında en erken çalıştır.
  3) Saf KV / ayar dosyalarını çevir (senkron kazancı en yüksek, risk en düşük):
